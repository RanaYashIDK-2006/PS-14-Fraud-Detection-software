## 4. Execution mode and real output

- **Mode: offline batch** — labelled in the report as *“offline batch
  (in-process PS-14 FusionEngine + RulesEngine + live decision policy)”*. The
  runner imports the Risk Engine's live `_evaluate_decision` policy and the
  calibrated `FusionEngine` from `models/artifacts` (fingerprint
  `sha256:b9252ee676c38d312b67471f892265e7`). This is **not** described as a
  live end-to-end service test; the separate Phase 19 live demo (15/15 checks
  through running `:8002`/`:8003`/`:8000`) covers that claim.
- Report artifact: `db/demo_batch/runs/RPT-20261011T060310Z-9d2cae/report.json`
  (gitignored runtime data), retrievable via `GET /demo/reports/{id}` and
  exportable via `/demo/reports/{id}/export`.

Observed results (verbatim from that report):

| Rows selected / scored / failed / skipped | 25,000 / 25,000 / 0 / 0 |
| Decisions | allow 24,188 (96.75%) · verify 640 (2.56%) · step_up 172 (0.69%) — reconciles to 25,000 |
| Risk score | min 1, max 85, mean 7.91 · ml_score max 0.122, mean 0.061 |

**Circularity statement (in the report itself):** labels come from the
generator's archetype injection, *not* from the rules being evaluated, so this
is not a rules-vs-itself evaluation — but the generator corpus shares its
pattern family with the training corpus, so offline metrics are **optimistic**
relative to out-of-distribution data. Synthetic demonstration only.
